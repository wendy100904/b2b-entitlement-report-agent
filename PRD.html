01背景与问题

B2B 客户成功团队为什么需要一个自动化权益分析工具

B2B 客户成功（Customer Success）团队每周需要人工翻阅大量企业客户的权益使用数据，回答三个问题：哪些客户临近流失、哪些有增购机会、本周该重点跟进谁。现状存在三处低效：

  • 靠人工翻表：逐条查看客户权益使用明细，容易漏判临期高风险客户。
  • 口径不统一：不同分析师对"健康 / 风险 / 续约"的定义不一致，报告结论难对齐。
  • 业务无法自助：非技术的业务同事想查数据只能反复提需求，等排期。

本项目把「上传数据 → 字段映射 → 批量风险诊断 → 生成可交付周报 → 自然语言查询」串成一条自动化链路，实现「上传即出报告」，并让业务同事用大白话直接查数。

02目标与非目标

目标

  • 将「客户权益使用 Excel/CSV → 可交付周报」的周期从小时级压缩到分钟级，且口径一致。
  • 用统一的风险分层模型（高危流失 / 中危预警 / 续费增购）帮助团队快速定位本周重点客户。
  • 提供自然语言查询，让非技术业务同事自助取数。

非目标（本期不做）

  • 不承接实时数据流 / 埋点接入，只处理按周快照的上传数据。
  • 不做账号体系、租户隔离、多用户权限（见边界，demo 阶段明确排除）。
  • 不做持久化数据库与跨实例共享（上传数据存进程内存，重启清空）。
  • 不承诺续约预测准确率，只输出规则可解释的分层评分与运营建议（SOP）。

03目标用户与场景

用户典型场景核心诉求
客户成功经理（CSM）每周一上传客户权益使用数据，查看续约风险分布与重点客户名单快速定位高危流失客户，获得运营建议
业务 / 运营同事想用自然语言问"本月哪些客户权益覆盖率低于 50%"不写 SQL 也能自助查数
团队负责人生成并导出本周可交付的图表化周报，同步给上下游一份口径统一、可直接交付的报告

05功能需求

按五个核心模块拆解，每项给出触发、行为、结果与验收

5.1 数据上传与字段映射

F1 · 上传 Excel/CSV （POST /uploads）

触发：用户在首页选择或拖入 .xlsx/.xls/.csv 文件。

行为：后端用 Pandas 解析；自动做字段模糊匹配（customer code、data date、industry、days to renewal 等）；处理缺失值；返回推断的列映射、预览行与列名。

结果：生成 session_id，进入字段映射确认页。

验收：上传合法文件后能拿到 session_id 与可读的预览表格；识别出的列名与建议映射高亮展示，供用户逐项确认或修改。

5.2 续约风险诊断

F2 · 风险分层与客户池 （POST /analysis/customer-pool）

触发：用户确认映射、筛选行业 / 续约窗口 / 价值档位后点击"开始分析"。

行为：后端按客户聚合（多周快照管理，默认取最新快照）；结合权益覆盖率、到期天数、使用趋势多维打分；输出高危流失 / 中危预警 / 续费增购分层；按行业、企业规模、活跃类型自动分群。

结果：返回批量 KPI、风险分布、行业汇总、运营 SOP、可导出的优先客户池。

验收：给定含临期低使用客户的数据，能将其正确划入"高危流失"并出现在优先客户池顶部；SOP 建议随风险层与分群变化。

5.3 图表化周报

F3 · 生成与导出周报 （POST /reports/weekly）

触发：用户在周报页设置报告标题与周标签。

行为：用 Plotly 生成图表化 HTML 周报（自包含）；浏览器端一键导出 PDF（A4 分页、图表防截断、颜色保真，无需后端依赖）。

结果：得到一份可直接交付的图表化周报，可下载 PDF。

验收：导出 PDF 后图表不截断、分页正确、颜色与网页一致；周报涵盖风险分布、KPI、客户名单。

5.4 自然语言数据问答

F4 · SQL Agent （POST /agent/sql-queries）

触发：用户在问答页用自然语言提问（如"权益覆盖率低于 50% 的客户有哪些"）。

行为：配置 OPENAI_API_KEY 时，Agent 将问题转为只读 DuckDB SQL 并上传数据上执行；未配置密钥或调用失败时，自动降级为规则化查询。

结果：返回查询结果（表格 / 图表）。

验收：配置密钥时能回答业务问题并只读执行；无密钥时仍能提供有限演示查询，核心流程不中断。

5.5 多周快照与周期选择

F5 · 历史周快照回看

行为：文件含"数据日期 / 统计日期 / 快照日期"时，保留每个客户-周快照；分析周期选择器默认取最新快照，可回看任意已上传的历史周。

验收：上传含多个快照日期的文件后，切换分析周期能正确回看对应周的数据。

06关键异常与降级

场景行为恢复方式
未配置 OpenAI 密钥SQL 问答降级为规则化查询，仅暴露有限演示查询配置密钥后自动恢复完整能力
字段识别不准确返回推断映射并高亮，用户逐项确认/修改人工修正后继续
上传数据缺关键字段提示缺失字段，风险模型降级计算或跳过对应维度补充字段后重跑
服务重启 / 多实例上传数据存进程内存，重启清空、多实例不共享明确标注 demo 边界，规划生产演进
当前无数据库边界：上传文件保存在进程内存，可供单实例并发用户使用，但重启即清空。生产落地需补充：SSO/API 鉴权、租户隔离、对象存储、元数据库、异步任务队列。

08非功能与边界

技术架构

  • 前端：原生 HTML/CSS/JS，FastAPI 同源托管，含导出 PDF。
  • 后端：FastAPI，12+ 版本化 REST 接口（/api/v1），Uvicorn 启动。
  • 数据：Pandas（清洗 / 聚合 / 指标）、DuckDB（内嵌只读 SQL 引擎）。
  • AI：OpenAI API 自然语言转 SQL；无密钥时规则化降级。
  • 可视化：Plotly 生成图表化 HTML 周报。

安全与合规

  • SQL 查询一律只读，防止通过问答写入或破坏数据。
  • 生产落地前必须补齐鉴权、租户隔离与对象存储，避免越权访问他租户数据。

09验收清单

  • 上传合法 Excel/CSV 后可完成字段自动识别 → 确认 → 风险诊断 → 周报 → 问答全链路。
  • 风险分层（高危 / 中危 / 增购）与优先客户池输出正确、可解释。
  • 周报可导出 PDF，A4 分页、图表不截断、颜色保真。
  • 配置密钥时 SQL Agent 能回答业务问题且只读执行；无密钥时规则降级可用。
  • 含快照日期的文件支持多周回看。
